### A Agent 与任务契约

- [A-01 人设工程：Role、Goal、Backstory 各管一件事](cards/A-01-人设工程-Role-Goal-Backstory-各管一件事.md)：role 定岗位，goal 定验收标准，backstory 定行事风格和边界，三句话决定这个 Agent 的行为上限。
- [A-02 委托开关：allow_delegation 是一条信息流向的声明](cards/A-02-委托开关-allow_delegation-是一条信息流向的声明.md)：允许委托的岗位能把活转给别人，代价是任务可能被踢来踢去，所以按信息流向决定开关。
- [A-03 Task 契约：用 Pydantic 把交付物钉死](cards/A-03-Task-契约-用-Pydantic-把交付物钉死.md)：expected_output 描述要什么，output_pydantic 定义字段和类型，下游拿到的就是可解析的对象。
- [A-04 context 参数：任务依赖用声明式表达](cards/A-04-context-参数-任务依赖用声明式表达.md)：Task 的 context 列上游任务，框架就会把上游产出塞进本任务的上下文，顺序和依赖一起确定。
- [A-05 Process：Sequential 保顺序，Hierarchical 加管理](cards/A-05-Process-Sequential-保顺序-Hierarchical-加管理.md)：Sequential 按任务顺序流水执行，Hierarchical 多一个管理者负责分派和验收。
- [A-06 多模态：本地图片先转 Base64，再交给视觉模型](cards/A-06-多模态-本地图片先转-Base64-再交给视觉模型.md)：AddImageToolLocal 把本地图片读成 Base64 塞进消息，模型侧指定 image_model 就能看图。

### T 工具与协议

- [T-01 工具设计哲学：从 API 到 Agent Tool 换的是调用方](cards/T-01-工具设计哲学-从-API-到-Agent-Tool-换的是调用方.md)：同一份能力，写成给人调用的 API 和写成给模型调用的工具，接口、报错、返回格式都不一样。
- [T-02 工具封装五步 SOP：定义、参数、语义重构、I/O 瘦身、错误转译](cards/T-02-工具封装五步-SOP-定义-参数-语义重构-I-O-瘦身-错误转译.md)：把一份 REST API 改成 Agent 能用的工具，五步各有各的坑，最容易被跳过的是语义重构和 I/O 瘦身。
- [T-03 MCP：把工具接口标准化，一次接入处处可用](cards/T-03-MCP-把工具接口标准化-一次接入处处可用.md)：MCP 服务器对外暴露工具清单，Agent 侧只配地址、过滤器和请求头，就能拿到一组标准工具。
- [T-04 Skills：先给菜单，再按需上菜](cards/T-04-Skills-先给菜单-再按需上菜.md)：工具描述里只放技能名和一句话摘要，模型选中之后才加载完整 SKILL.md，上下文只花一次钱。
- [T-05 沙箱两件套：代码解释器加无头浏览器](cards/T-05-沙箱两件套-代码解释器加无头浏览器.md)：AIO-Sandbox 容器里同时提供代码执行、文件操作和浏览器，Agent 因此能算数、能上网、能手写文件。
- [T-06 中间结果工具：给 Agent 一个草稿本](cards/T-06-中间结果工具-给-Agent-一个草稿本.md)：IntermediateTool 把中间产出落成文件，Agent 后面可以只读摘要，上下文不会被半成品占满。

### X 上下文与记忆

- [X-01 从 Prompt 到 Harness：Bootstrap 四件套](cards/X-01-从-Prompt-到-Harness-Bootstrap-四件套.md)：每次开工先拼四段骨架：我是谁、服务谁、怎么干、记得什么，拼完再交给模型。
- [X-02 剪枝：把旧工具结果换成占位符，结构还得合法](cards/X-02-剪枝-把旧工具结果换成占位符-结构还得合法.md)：倒数第 N 轮之前的工具返回全部替换成「已剪枝」，tool_call_id 保留，消息结构不能坏。
- [X-03 压缩：用量超过 45% 就把历史摘要成一段](cards/X-03-压缩-用量超过-45%-就把历史摘要成一段.md)：token 用量接近模型上限时，把早期对话分块摘要成一条 context_summary，最近十轮保留原文。
- [X-04 文件系统记忆：主 Agent 不碰文件，写记忆走技能](cards/X-04-文件系统记忆-主-Agent-不碰文件-写记忆走技能.md)：主 Agent 只留一个 SkillLoaderTool，写记忆的活交给子 Crew 在沙箱里做，权限和格式都收在技能里。
- [X-05 搜索式记忆：异步索引加混合检索](cards/X-05-搜索式记忆-异步索引加混合检索.md)：对话结束后异步跑四步索引，存进 pgvector，检索时向量和全文按 7:3 加权。
- [X-06 三层记忆：短期上下文、长期文件、海量检索](cards/X-06-三层记忆-短期上下文-长期文件-海量检索.md)：XiaoPaw 把记忆分成三层，按成本和速度取舍，最近的放上下文，常用的放文件，海量的进向量库。
- [X-07 记忆治理：谁写入、谁审计、谁清理](cards/X-07-记忆治理-谁写入-谁审计-谁清理.md)：记忆会越写越乱，所以要有治理技能：定期审计冲突条目、清理过期内容、合并重复项。

### O 多智能体协作

- [O-01 Orchestrator：角色在运行时由主 Agent 创建](cards/O-01-Orchestrator-角色在运行时由主-Agent-创建.md)：主 Agent 手里只有三个工具：生成子 Agent、并行生成、读产出文件，团队结构由它当场决定。
- [O-02 数字团队：一个通用类，装不同的 workspace](cards/O-02-数字团队-一个通用类-装不同的-workspace.md)：DigitalWorkerCrew 只有一份代码，角色差异全在 workspace 的四个 markdown 和技能目录里。
- [O-03 角色体系：NEVER 清单比职责描述更管用](cards/O-03-角色体系-NEVER-清单比职责描述更管用.md)：每个角色的 agent.md 里写清不做什么，越界时模型会主动退回，而不是硬着头皮做。
- [O-04 任务链与邮箱：三态状态机保证消息不丢不重](cards/O-04-任务链与邮箱-三态状态机保证消息不丢不重.md)：任务通过邮箱传递，状态只有 unread、in_progress、done，取件是原子操作，超时自动回收。
- [O-05 Human as 甲方：三个介入点，一个接口](cards/O-05-Human-as-甲方-三个介入点-一个接口.md)：人在环不靠模型自觉，由编排脚本在固定时点停下来等人确认，而且人只跟 Manager 对话。
- [O-06 自我进化：Skill 管怎么想，Script 管查什么](cards/O-06-自我进化-Skill-管怎么想-Script-管查什么.md)：复盘技能给出思考框架，日志查询脚本负责取数，Agent 产出结构化的改进提案，审批后才改文件。

- [E-04 三个可靠性策略：重试追踪、成本围栏、循环检测](cards/E-04-三个可靠性策略-重试追踪-成本围栏-循环检测.md)：一个记失败率，一个卡预算，一个揪重复状态，三个策略挂在同一套 Hook 上，顺序还有讲究。

- [E-06 SecureToolWrapper：密钥在工具层注入，模型全程看不到](cards/E-06-SecureToolWrapper-密钥在工具层注入-模型全程看不到.md)：密钥不写进 backstory，也不写进工具描述，包装器在执行那一刻从环境变量取出并合并进参数。

## 视频要点怎么来的

每讲按固定间隔抽帧，用 macOS Vision 做中英 OCR，去掉水印和重复画面后按时间轴压缩成要点。第 01 至 08 讲为全文逐帧 OCR，其余讲为等距 12 帧抽样。
