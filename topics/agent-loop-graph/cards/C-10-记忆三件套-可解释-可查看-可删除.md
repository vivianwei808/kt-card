# C-10 记忆三件套：可解释、可查看、可删除

> 说不清为什么记、看不到记了什么、删不掉记错的内容，这样的记忆系统不该上线。

## 机制

- 可解释：每条偏好记录它从哪几次会话学来，能给用户出示证据。
- 可查看：用户能看到系统都记了什么，才知道有什么可删。
- 可删除：支持单条遗忘、整体清空、关闭偏好学习。
- 三件里缺前两件，删除权就是空的。
- 记忆记错的代价远大于意图识别记错：识别错了用户立刻能纠正，记忆错了用户根本不知道。
- 策略按代价分级：记错代价低的用隐式推断，代价高的用显式确认，有上下文依赖的带条件标签。
- 偏好属于个人数据，导出、清空、关闭三项属于合规底线。

## 代码落点

- `UserProfile / Preference`：来源 sessions 字段
- `ProfileController`：查看与删除接口
- `PREFERENCE_LEARNED / CONFIRMED / FORGOTTEN 三类事件`

## 复用清单

- 做用户画像前先设计「用户如何查看和删除」。
- 写入时记录来源，读取时才敢解释。

## 面试一句话

记忆系统最危险的属性是忘不掉；可解释、可查看、可删除是上线门槛。

## 常见坑

先做学习效果，合规和可解释留到以后。以后通常不会来。
