# C-07 偏好晋升三条判据

> 频次至少 3 个会话、方向一致、有条件就连条件一起确认。

## 机制

- 频次门槛：同一修改模式出现在至少 3 个不同会话。同会话反复改只算一次。
- 方向一致性：4/5 次改成民宿是强信号；2 次上调 2 次下调是浮动，不能晋升。
- 上下文一致：「带孩子不爬山」可以晋升，但必须连条件一起保存，不能写成无条件的「不爬山」。
- 三个判据对应四行代码：WAIT、REJECT、CONFIRM_WITH_CONDITION、CONFIRM_UNCONDITIONAL。
- 无论哪种候选，用户确认前都不能写入画像。
- 晋升判断表看五个例子：连锁酒店改民宿 4 次一致，确认后写入；预算加 400 五次里两次，不能晋升。

## 代码落点

- `PreferenceLearner.java`：analyze() 只做汇总，不做决定
- `PromotionPolicy.java`：evaluate() 四个分支
- `PreferenceCandidate.java`：sessionCount / directionConsistent / condition
- `looptrip.preference.min-sessions=3`

## 复用清单

- 任何「从行为里学偏好」的功能，都需要频次、方向、条件三道过滤。
- 把汇总与决策拆成两个类，便于单测和解释。

## 面试一句话

偏好晋升有三道门槛：频次、方向、条件；达不到就继续观察，达到也要用户点头。

## 常见坑

一次修改就写进画像。用户下次发现系统「自作主张」，却找不到原因。
