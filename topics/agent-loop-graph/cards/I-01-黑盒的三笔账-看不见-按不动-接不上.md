# I-01 黑盒的三笔账：看不见、按不动、接不上

> 同一份执行信息迟到了 27 秒；用户既不能叫停，也不能带着上一版修改。

## 机制

- 看不见：系统内部一直在发事件，浏览器只拿到最后一次性响应。信息不缺，信息迟到。
- 按不动：取消信号恒为 false，提交后没有第二个入口。用户改主意只能等跑完。
- 接不上：改预算要从零重跑，状态只活一次请求，Loop 没有家。
- 三笔账同一个病根：同步 HTTP 只给了一个入口、一个出口、零个持久位置。
- 解法在协议层：把「一次请求」换成「一段会话」。页面动画解决不了这个病根。
- 还有第四笔账：听不懂。入口通了，用户说的还是「太贵了」，不是 budget=3000。

## 代码落点

- `PlanController`：同步 POST /api/plan/ask，只有一个出口
- `PlanningEventSink`：事件早已存在，缺的是推送到前端的通道
- `PlanningSession`：第七、八章补上的持久位置

## 复用清单

- 评估任何长耗时 AI 功能，先算这三笔账：用户能不能看见、能不能停、能不能改。
- 病根通常在协议层，不在 UI 层。

## 面试一句话

黑盒的代价可以量化：续修从 21000 token 降到 8900，取消等待从几十秒降到 0。

## 常见坑

用更精致的加载动画解决等待焦虑。动画不传递任何决策信息。
