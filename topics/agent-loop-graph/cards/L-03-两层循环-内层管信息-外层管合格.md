# L-03 两层循环：内层管信息，外层管合格

> 框架的工具循环解决「信息够不够」，我们写的业务循环解决「结果行不行」。

## 机制

- 内层循环在 .call() 内部：模型返回 tool_calls 就执行工具，结果追加进消息数组，直到模型不再请求工具。
- 内层只回答一个问题：这次回答所需的事实凑齐了吗。它不检查预算、不管业务目标、不会主动重做。
- 外层循环由宿主编写：生成、评审、带反馈重来，停止条件在程序里。
- 外层一轮等于内层一整趟。日志上一轮可能对应四次工具调用、六七次模型请求。
- 内层对我们基本是黑箱，外层完全可控：可以发事件、可以上页面、可以断言。
- 两层的账都记在我们头上，能刹车的地方只在外层。

## 代码落点

- `ChatClient.prompt().tools(...).call()`：内层，由 Spring AI 驱动
- `TravelPlanningEngine.runLoop()`：外层，for 轮次 + 预检 + 护栏
- `PlanningEventType.ROUND_STARTED / TOOL_CALLED`：外层可见性

## 复用清单

- 画架构图时把两层分开画，标注各自的停止条件与负责人。
- 监控与预算挂在外层；内层的调用次数只做参考。

## 面试一句话

Agent 里有两个循环：内层是框架的工具循环，外层是我们的业务循环；停止权只在外层。

## 常见坑

把两层混成一层。想跑三轮却发了十几次请求，token 账对不上，何时停也说不清。
