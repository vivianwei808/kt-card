# L-06 循环与重试的分界线：问题有没有进入下一轮

> 重试是同一张卷子重考，循环是老师圈出错题再答一遍。

## 机制

- 重试：同样的输入再发一次，期待这次运气好。没有新信息，收敛靠概率。
- 循环：上一轮的问题清单作为输入进入下一轮，模型知道自己错在哪。
- 回放证据：no-feedback 场景里第 2 轮 feedbackReceived = false，两轮一模一样地失败，花了两轮的钱。
- 差别只是一个字段，代价是两轮的 token。
- 第 2 轮不是「再试一次」，是「在知道自己错在哪的前提下再做一次」。
- 反馈必须能承接：状态里要有地方放问题，Prompt 里要有位置放问题。

## 代码落点

- `PlanningRoundSnapshot.feedbackReceived`：回放断言的关键字段
- `TravelPlanningEngine.buildRepairInput()`：把 problems 带进下一轮
- `Chapter4FeedbackReplayTest`：success / feedback / no-feedback / max-rounds 四个场景

## 复用清单

- 给循环加一个断言：第 2 轮必须收到第 1 轮的问题。
- 没有这个字段，你无法区分「在学」和「在重复」。

## 面试一句话

我用 feedbackReceived 这个字段把循环和重试分开；没有反馈的循环只是重复付费。

## 常见坑

把「多跑几轮」当优化。没有反馈的多轮，成本线性增长，质量原地不动。
