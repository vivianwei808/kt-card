# G-05 等价迁移怎么证明没改坏

> 输入相同、关键轨迹相同、结果相同，旧测试不改也能过。

## 机制

- 三条业务轨迹先固定：正常、返工、入口失败。
- 正常：START 到 preflight 到 generate 到 validate 到 END，模型调用 1 次。
- 返工：validate 到 generate 再 validate；不重做 preflight。
- 入口失败：preflight 直接到 PREFLIGHT_FAILED，模型调用 0 次。
- 验收断言：终态、业务轮次、模型调用次数、事件序列。
- 只要有一条对不上，比如返工多记一轮、预检失败调了模型，就是改写，必须回头查。
- 界面看不出 Loop 变 Graph，等价迁移的结构证据只在测试里。

## 代码落点

- `Chapter9GraphMigrationReplayTest`：轨迹与调用次数断言
- `PlanningArchitectureTests`：结构边界
- `scripts/course/ch09-s2-graph-migration.sh`

## 复用清单

- 重写控制流前，先录一组基线与调用次数。
- 等价性用测试证明，不用肉眼读代码证明。

## 面试一句话

等价迁移的证明是旧测试零改动通过，加上关键轨迹与调用次数对得上基线。

## 常见坑

只看最终结果相同。路径变了，可能多花钱或跳过了某个检查。
