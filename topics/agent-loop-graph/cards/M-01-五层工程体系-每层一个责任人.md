# M-01 五层工程体系：每层一个责任人

> Prompt 说清动作，Context 带齐材料，Harness 守住边界，Loop 依证据修正，Graph 安排整体结构。

## 机制

- 五层是职责叠加，后一层不替换前一层。简单任务可以没有显式 Loop 或 Graph，但不能让 Prompt 偷偷承担验证、停止或调度责任。
- 每层有自己的失败形态：Prompt 失败是答非所问，Context 失败是材料过期或缺失，Harness 失败是停不下来，Loop 失败是原地打转，Graph 失败是依赖与并行失控。
- 排障时按层定位：跑偏查 Prompt，过期查 Context，停不下查 Harness，重复错查 Loop，结构乱查 Graph。
- 对应的岗位能力也分五层：Prompt Engineer、Context Engineer、Harness Engineer、Loop Engineer、Graph Engineer。五层都做过一遍，才谈得上 Agent 应用开发的完整交付链。

## 代码落点

- `PlanChatService.buildPrompt()`：Prompt 层：角色、输出契约、事实纪律
- `ContextAssembler.java`：Context 层：四分区组装、预算淘汰
- `LoopGuardrail.java`：Harness 层：每轮花钱前的四道检查
- `TravelPlanningEngine.java`：Loop 层：预检、生成、验收、反馈、bestRound
- `TravelGraphFactory.java`：Graph 层：8 节点 16 边的声明

## 复用清单

- 新项目开工先画这五层，缺哪层补哪层，不按框架名选型。
- Code Review 时对每段代码追问一句：它属于哪一层的责任？跨层就是未来的 bug。
- 面试或述职用这张表定位自己站在哪层，下一层怎么补。

## 面试一句话

我把 Agent 拆成五层职责，每层有独立的失败模式和验证手段；我做的项目五层都有落地代码。

## 常见坑

把所有要求塞进系统提示词。短期能跑，出错时无法判断是模型、上下文还是控制流的问题。
