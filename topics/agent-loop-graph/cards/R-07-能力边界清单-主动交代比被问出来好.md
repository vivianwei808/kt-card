# R-07 能力边界清单：主动交代比被问出来好

> 本地快照、非生产 SLA、单 Agent、规则预设、取消仅尽力、Graph 不天然提速。

## 机制

- 数据边界：本地 JSON 快照，不代表真实库存、实时价格或线上流量。
- 性能边界：同条件计时只在教学数据与指定日期范围内成立，非生产 SLA。
- 架构边界：单 Agent 系统，规则由代码预设；四个并行节点是 Java 数据节点，不是四个 LLM Agent。
- 并发边界：取消是尽力通知，不承诺远端硬中止；迟到结果坚决不采用。
- 权限边界：四个只读工具不等于完整权限隔离，身份、授权、审计属于生产化工作。
- 依赖分析边界：已知字段的变更白名单，不是通用依赖分析引擎。
- 主动划边界不会减分，反而证明你知道系统在哪里会坏。

## 代码落点

- `第10章 22/36 的能力边界列`
- `application.yml`：快照数据源与模型配置
- `PlanningStopReport`：取消与停止的诚实表达

## 复用清单

- 每个项目准备五条边界，写进自我介绍最后一句话。
- 边界要具体到「证明不了什么」，不要写「还有很多不足」。

## 面试一句话

它能证明覆盖条件下的闭环行为，证明不了生产 SLA 和真实库存；这两件事我没有做。

## 常见坑

把教学项目说成生产系统。第一个追问就会暴露。
