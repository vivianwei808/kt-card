# H-02 三层根因：模型、系统、交互

> 模型没有资源观和元认知，系统缺少外部观测与预算，交互目标模糊且环境不确定。

## 机制

- 模型层四个缺陷：没有资源感知、完成偏差、无法区分重复与迭代、对环境故障盲区。
- 系统层三个缺失：缺乏外部观测、缺乏预算边界、错误反馈不完整。
- 交互层两个触发条件：目标定义模糊、环境非确定性。
- 「帮我优化这段代码」没有可量化的停止条件，模型永远可以再优化一点。
- 同一 API 这次正常下次超时，前后矛盾的反馈让模型行为更难预测。
- 任何只被告知「完成任务」、没被告知「什么时候放弃」的系统，时间线足够长就一定会失控。

## 代码落点

- `LoopGuardProperties`：预算与时长的显式边界
- `PlanningStopReport`：外部观测与停止原因
- `TravelPlanPreflight`：目标可执行性的前置判断

## 复用清单

- 设计护栏前先归因：是模型缺陷、系统缺失还是需求模糊。
- 能靠需求澄清解决的，不要用护栏硬拦。

## 面试一句话

失控有三层根因；护栏治的是系统层，需求澄清治的是交互层，换模型基本治不了。

## 常见坑

所有问题都归因于模型。改 Prompt 治不了没有预算边界这件事。
