# I-05 脱敏白名单：新字段默认不安全

> 只有名单上的 key 才放行；白名单跟判据长，犯错方向永远是「少推了」。

## 机制

- 白名单：列出来的才能出去，新字段默认安全（此处指默认不出去）。
- 黑名单：列出来的不出去，新字段默认危险（默认会泄露）。
- 这条管道过公网，DevTools 谁都能开，必须按最坏情况设计。
- 第一版只放行三个标量；候选、选择结果、摘要是后来按判据逐个批进来的。
- 一个字段一旦推出去，你不知道另一端有谁在接。
- 测试要主动喂 apiKey、prompt、stackTrace，断言它们出不去。

## 代码落点

- `SsePlanningEventSink.emit()`：16 个 key 的白名单
- `SsePlanningEventSinkDesensitizationTests`：泄漏断言
- `REVIEW_COMPLETED 只放 problemsCount 的做法`

## 复用清单

- 所有对外推送都走一个统一 emit 方法，白名单集中维护。
- 给脱敏写专门的测试，不要靠 code review 保证。

## 面试一句话

推送用白名单不用黑名单；新字段默认不出去，宁可少推，不能多漏。

## 常见坑

用黑名单屏蔽敏感字段。新增一个字段就多一次泄漏机会。
