# L-01 Function Calling 的本质：模型只开口，程序才动手

> 模型说出想调什么，Java 进程真正执行；权限、失败、账单都留在宿主一侧。

## 机制

- 一次工具调用是三段接力：模型提出请求，程序执行查询，模型看着真实结果续写。
- 模型没有执行任何代码，它只负责「说要什么」。能惹多大麻烦，取决于我们在玻璃房外放了哪几个按钮。
- 我们提供四样东西：工具名、参数契约、返回结构、执行实现。前三样合起来就是一份写给模型看的 API 文档。
- 执行权不在模型手里，这是「装手」这个比喻最容易被误解的地方。
- 装上工具后一轮可能包含多次往返：先查航班、再查酒店、又查景点。所以会更慢，也更费 token。

## 代码落点

- `TravelTools.java`：四个 @Tool 方法：searchFlights / searchHotels / searchAttractions / queryWeather
- `TravelDataService.java`：真正执行查询、城市归一化、条件过滤
- `ChatClient.prompt().tools(travelTools).call()`：注册工具并启动内层循环

## 复用清单

- 给模型开放工具前，先写清楚四样：名字、参数、返回、查不到怎么办。
- 工具一律先只读。写操作、支付、改库权限留到有幂等键和人工确认之后。

## 面试一句话

工具调用里模型只负责选择，执行权和账单在我们手里；这是 Agent 安全和成本控制的第一道边界。

## 常见坑

以为模型会执行代码。把权限校验写在工具描述里，等于没写。
