# G-01 Loop 是 Graph 的特例

> while 的一条回边，就是图上的一条边；图不替代 Loop，它把控制流展开。

## 机制

- Loop 像环形公交线：简单清楚，但画不出哪几条能同时走。
- Graph 像城市交通图：环线、分叉、汇合、换乘都能画出来。
- Loop 答不上三个问题：哪些步骤能同时干、失败只需重做哪一段、走到哪里该停下来等人。
- 图化不动 Prompt、Context、Harness 的职责，只把藏在循环里的控制流拎出来，变成可声明的节点和边。
- 回边落在哪，返工范围就停在哪。
- 一份声明同时驱动执行、测试、可视化，这是图化最大的结构收益。

## 代码落点

- `GraphDefinition`：节点、边、终态的声明
- `LightGraph`：声明式执行器
- `TravelGraphFactory`：8 节点 16 边

## 复用清单

- 面对缠在一起的 if-else 和 while，先问一句：这个能不能画成图？
- 画得出来、别人看得懂，麻烦就解决了一半。

## 面试一句话

Loop 是 Graph 的特例，while 的回边在图上就是一条边；图化的价值是让控制流可声明、可测试、可展示。

## 常见坑

把 Graph 当成新框架重写业务。业务行为不变，只该改控制流的表达方式。
