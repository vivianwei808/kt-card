# C-08 召回与遗忘：记忆越准越好

> 相关性挑前 8 条；90 天未用降置信度 0.25，低于 0.3 自动删除。

## 机制

- 召回三道过滤：字段相关、条件匹配、时间新鲜。
- 字段相关：这次请求涉及哪个领域，只召那个领域的偏好。餐饮偏好不放进节奏请求。
- 条件匹配：带「带孩子」条件的偏好，在不带孩子时必须不召回。放进去比不放更糟。
- 时间新鲜：上周确认的排在三个月前的之前。
- 排序后取前 max-recall = 8 条。全塞会超预算，整区丢弃又等于白学。
- 遗忘是一等公民：90 天未召回降 0.25，低于 0.3 移除；相反修改直接删除旧记录。

## 代码落点

- `PreferenceMemoryService.java`：召回与衰减
- `looptrip.preference.max-recall=8 / decay-days=90 / decay-drop=0.25 / delete-threshold=0.3`
- `Preference / PreferenceCandidate`：条件、置信度、来源会话

## 复用清单

- 召回前先过滤条件，别把不适用的偏好塞进 prompt。
- 给每条记忆定一个可执行的过期规则，否则只写不删。

## 面试一句话

记忆质量取决于召回准不准，不取决于存了多少条；过期与删除必须有明确规则。

## 常见坑

只做写入不做遗忘。错误偏好永远留在系统里，用户还感知不到。
