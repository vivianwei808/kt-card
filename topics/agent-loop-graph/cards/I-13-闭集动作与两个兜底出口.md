# I-13 闭集动作与两个兜底出口

> 六个进 Loop 的动作，三个不进的出口；输出空间不能大于执行空间。

## 机制

- 进 Loop：REVISE_BUDGET、REVISE_HOTEL_PRICE、ADD_MUST_VISIT、ADJUST_PACE、CANCEL、ROLLBACK。
- 不进 Loop：NEW_SESSION、ASK_QUESTION、UNKNOWN。
- 分类器最危险的属性是永远给你一个答案。输出空间里必须显式留出「我不知道」这一格。
- UNKNOWN 必须是动作枚举里的合法值；异常和 null 都不算。
- ASK_QUESTION 的价值更大：用户问「雷峰塔几点关门」，误判成改需求会烧掉三轮钱。
- 识别成功和执行允许是两件事：NEW_SESSION 识别准确，但结论是「这个会话里不能做」。
- 动作的性质挂在枚举上：requiresSlots、requiresConfirmation、dispatchesOperation。

## 代码落点

- `PlanningIntentAction`：九个枚举与三个性质方法
- `PlanningIntentGate.decide()`：缺槽位澄清、确认、执行
- `PlanningChatZeroEngineTests`：证明门说不等于引擎没被碰

## 复用清单

- 定义意图枚举时，先加 UNKNOWN 和 ASK_QUESTION 两个出口。
- 把「要不要槽位、要不要确认、要不要派发」写进枚举，不要写在 if-else 里。

## 面试一句话

我的动作集合是闭集，并显式保留 UNKNOWN 与 ASK_QUESTION；识别成功不等于允许执行。

## 常见坑

允许模型输出系统做不到的动作。识别越准确，用户得到的失败越莫名。
