# C-06 四层记忆：按生命周期分层

> 工作记忆、会话记忆、用户记忆、系统知识，四种寿命，四个隔层。

## 机制

- L1 工作记忆：当前轮次，存本轮方案与 problems，下一轮直接覆盖。
- L2 会话记忆：当前会话，存版本链与 requestDiff，会话结束回收。
- L3 用户记忆：跨会话持久，存已确认偏好、置信度、条件、来源会话。
- L4 系统知识：全局静态，存群体先验（每天不超过 4 个景点、换乘至少 40 分钟），新用户靠它兜底。
- 分层的判据是寿命，不是重要性。按重要性分会让临时信息永久化。
- 会话记忆是缓冲区：修改先观察，达到门槛并经用户确认，才升入用户记忆。

## 代码落点

- `PlanningLedger`：L1 工作记忆
- `PlanningSession / PlanningVersion`：L2 会话记忆
- `data/profiles/{userId}.json`：L3 用户记忆
- `looptrip.constraints.*`：L4 系统知识

## 复用清单

- 设计记忆系统先画时间轴：活一轮的、活一次会话的、活一辈子的，各放各的。
- 把产品默认值放系统层，不要混进用户画像。混了以后用户不知道该删什么。

## 面试一句话

我按生命周期把记忆分成四层；层次之间靠显式晋升条件连接，不会自动扩散。

## 常见坑

只分短期和长期两层。临时修改要么丢失，要么被永久化，两种都错。
