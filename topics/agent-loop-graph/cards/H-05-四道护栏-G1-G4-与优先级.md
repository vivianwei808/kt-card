# H-05 四道护栏 G1-G4 与优先级

> 无进展、Token 预算、总超时、轮次上限；按信息量从高到低排序，第一条触发即停。

## 机制

- G1 无进展：连续 N 轮 HARD 失败指纹完全相同。它告诉用户问题出在需求或数据。
- G2 Token 预算：已用加下一轮预估超过上限。它告诉用户钱不够了。
- G3 总超时：挂钟时间累计超限，用于防卡死。
- G4 轮次上限：唯一不依赖外部测量的护栏，最后一根保险丝。
- 优先级由信息量决定：报「连续两轮完全相同」，用户知道该改需求；报「达到最大轮次」，用户只会想多跑几轮。
- 从十种候选里筛出这四道，标准是信息量、实现成本、误判率。
- 护栏限制失控，不缩短 Loop。三轮收敛的场景里 G1 正确未触发。

## 代码落点

- `LoopGuardrail.java`：G1_NO_PROGRESS / G2_TOKEN_BUDGET / G3_TOTAL_TIME / G4_MAX_ROUNDS
- `looptrip.max-tokens=20000 / max-duration=5m / multiplier=1.2 / same-fingerprint-limit=2`
- `PlanningLedgerEntry.hardFailureFingerprint`：指纹来源

## 复用清单

- 先上轮次与超时保底，再加 Token，最后加无进展。
- 每道护栏触发时都要能说清「谁拦的、为什么、证据、建议」。

## 面试一句话

四道护栏按信息量排优先级：无进展最有解释力，轮次最笨但最不可省。

## 常见坑

只设最大轮次。空转、卡死、预算爆炸它都管不了。
