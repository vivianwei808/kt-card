# C-05 两把尺子：单页预算与总账预算

> context.max-tokens 管单次 prompt 多长，looptrip.max-tokens 管整次规划花多少钱。

## 机制

- looptrip.context.max-tokens = 6000，是 ContextAssembler 的排版尺，只量 system 与 user 文本。
- looptrip.max-tokens = 20000，是 Harness 的总账护栏，管整次规划累计消耗。
- 两把尺子混用会出现两种事故：把总账当单页，prompt 被砍到不可用；把单页当总账，循环跑穿预算。
- token 估算用字符数近似，中文、JSON、英文混排没有稳定系数，必须预留安全余量。
- 估算器不是供应商账单，命名上要标明「估算」，避免被当真。

## 代码落点

- `ContextProperties.java`：looptrip.context.*
- `LoopGuardProperties.java`：looptrip.max-tokens / max-duration / multiplier
- `application.yml`：两处配置并列存在

## 复用清单

- 做预算类功能，先区分「单次上限」和「累计上限」，各自命名清楚。
- 估算值一律配安全余量，宁可少放一段，不要刚好塞满。

## 面试一句话

项目的预算有两个层级：单页 6000 管排版，总账 20000 管花费；混用是常见事故。

## 常见坑

用一个 max-tokens 同时管两件事。语义不清，调参时必然顾此失彼。
