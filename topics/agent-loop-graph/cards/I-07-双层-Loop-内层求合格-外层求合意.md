# I-07 双层 Loop：内层求合格，外层求合意

> 引擎自动跑到合格，人只判断机器判断不了的那部分。

## 机制

- 内层 Loop 由引擎驱动：生成、验收、反馈、再生成，目标是合格。
- 外层 Loop 由人驱动：提需求、看过程、判合意、改需求或接受。
- 两层各求一件事：内层求合格，能被代码判定；外层求合意，只能被人判定。
- 人在环不等于人参与每一步。每轮都要点继续，那是把手工作业包装成自动化。
- 默认自动跑，人随时可以插手。门开着，但不强迫你走进来。
- 「我想住民宿」六个校验器一个都判不了，这类标准只能放在外层。

## 代码落点

- `TravelPlanningEngine`：内层
- `PlanningSessionStore + PlanController`：外层入口
- `PlanningIntentGate`：人的输入转成结构化动作

## 复用清单

- 把验收标准分成「代码能判」和「只能人判」两组，分别挂到内外两层。
- 外层只提供开口，不要求人逐步确认。

## 面试一句话

Agent 是双层 Loop：内层自动求合格，外层由人求合意；两层共享状态，不共用预算。

## 常见坑

把所有判断都交给人。系统退化成需要不停点确认的脚本。
