# R-02 简历项目块：可直接粘贴的版本

> 一个标题、一句职责、四条 bullet，每条一个机制加一个证据，末尾主动交代边界。

## 机制

- LoopTrip 旅行规划 Agent｜个人实战项目
- 技术栈：Java 21 / Spring Boot 3.5.8 / Spring AI 1.1.2；本地 JSON 事实快照，不代表真实库存、线上流量或生产 SLA。
- 个人职责：负责输出契约、上下文组装、执行控制与状态模型，完成 Loop、Harness 护栏与 Loop 到 Graph 的迁移。
- 第一条：以 TripPlan Schema 约束模型输出，按指令、约束、历史、画像四分区组装上下文，记录 included/dropped，并用测试验证紧预算下关键约束仍被保留。
- 第二条：将航班、酒店、景点、天气封装为四个只读 Tool，以「查不到就说没有」的事实纪律约束模型；用契约层与 C1-C7 交付层两层验收，problems.isEmpty() 作为唯一通过条件。
- 第三条：引入预检与 G1-G4 四道护栏（无进展、Token、超时、轮次），输出六种终态与停止报告；用脚本化回放与 calls 断言证明「下一次调用未发生」。
- 第四条：把串行 Loop 等价迁移为 8 节点 16 边图：四路事实并行与 ALL 汇合、awaitUser 中断与快照恢复；结构断言与故障注入覆盖依赖、降级、迟到结果与恢复。
- 只写你真跑过、能复现的部分。课程代码可以复现，跑不通的部分不要写。
