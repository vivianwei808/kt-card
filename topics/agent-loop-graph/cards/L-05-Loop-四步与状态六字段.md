# L-05 Loop 四步与状态六字段

> 决策、执行、观察、判断；前两步决定能不能干活，后两步决定能不能被信任。

## 机制

- 决策：这一轮做什么。第一轮从零创作，后续轮按反馈修订，不要每轮用同一个 Prompt 重生成。
- 执行：真正调模型，也是唯一花钱、唯一会外部失败的一步。护栏检查放在它之前。
- 观察：把输出变成可检查的东西。本章只做契约级检查：天数、住宿、景点、总花费那一行。
- 判断：两个出口。软完成是契约通过，硬停止是轮次用尽。两个出口都返回结果对象，不抛异常。
- 状态六字段：原始需求、当前方案、检查结果、返工问题、轮次、过程记录。
- 第 2 轮 Prompt 必须带三样：用户需求、上一版全文、问题清单，并要求保留已合格部分。
- 事件必须先于页面存在：今天先收集成列表，后面改成 SSE 推送时不用重写 Loop。

## 代码落点

- `PlanningRoundSnapshot`：轮次、请求、行程、模型、耗时、problems、constraintResults、feedbackReceived、事件
- `PlanGenerationInput`：需求、轮次、上一版、反馈四件
- `PlanningEvent / PlanningEventSink`：过程记录与推送接口

## 复用清单

- 任何循环都先定义这六个状态字段，再写代码。
- 把「观察」和「判断」做成纯函数，便于单测和回放。

## 面试一句话

我的一轮是四步：决策、执行、观察、判断；状态用不可变 record 跨轮传递，反馈字段是循环与重试的分界。

## 常见坑

每轮从零重生成。上一版被扔掉，反馈没有着力点，方案在几种可能之间摇摆。
