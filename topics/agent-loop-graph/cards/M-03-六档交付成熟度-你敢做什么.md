# M-03 六档交付成熟度：你敢做什么

> 能跑、能交付、能托管、能对话、能进化、能拆结构，每档对应一句「你敢在什么条件下用」。

## 机制

- 能跑（第3-4章）：敢自己盯着跑。页面有输出，链路能通，人守在旁边。
- 能交付（第5章）：敢给用户用。HARD 标准全部由程序算，通过才亮绿灯。
- 能托管（第6章）：敢没人盯着跑。成本有界、终止可靠、失败诚实。
- 能对话（第7章）：敢让用户在旁边看着、插着话跑。过程可见、随时可停、改完能续。
- 能进化（第8章）：敢放手让它越用越好。修改留下痕迹，晋升有门槛，遗忘可执行。
- 能拆结构（第9章）：敢把控制流交给团队。并行、等待、局部返工都画在图上，执行、测试、展示同源。
- 六档讲的是「成熟度」，不是「层数」。五层工程体系始终在，六档只是每层的能力厚度。

## 代码落点

- `PlanStatus / PlanningTerminalState`：每档在终态与响应结构上的差别
- `PlanningRoundSnapshot`：交付档之后才有的逐轮记录
- `LightGraph + GraphViewController`：拆结构档的结构证据

## 复用清单

- 写简历或述职时，先说自己稳定站在哪一档，再说下一档补什么。
- 评估外包或采购的 Agent 产品，用这六档问对方敢承诺到哪。

## 面试一句话

我的项目稳定在「能托管 + 能对话」，Graph 部分做到「能拆结构」的教学级执行器，生产级治理还没做。

## 常见坑

把 Demo 当交付。能跑只是第一档，中间还差验收、护栏、可观察性。
