# I-06 可观察性不得控制主流程

> emit 里 catch 掉所有异常，注释只有一句：观测不能控制规划流程。

## 机制

- 事件推送失败时，规划必须照常跑完。
- sink 抛异常不能影响 Loop，前端断开也不能让后端回滚。
- 第 6 章就写好的 emit 方法，第 7 章接入整条 SSE 通道时一行没改。
- session 为 null 时直接返回：67 个老测试一行不改，新通道对旧路径无感。
- 并联的技术含义：新通道可以独立失败，旧路径完全不受影响。
- 可观察性挂在旁路上，主链路不依赖它。

## 代码落点

- `TravelPlanningEngine.emit()`：try/catch 吞掉 RuntimeException
- `SsePlanningEventSink`：推送实现
- `注释原文`：Observability must not control the planning flow.

## 复用清单

- 所有埋点、日志、事件推送都包一层保护，失败只降级不抛出。
- 新增通道时先跑旧测试，确认零改动通过。

## 面试一句话

可观察性必须能单独坏掉；观测失败不应该让业务失败。

## 常见坑

让推送异常冒泡，一次前端断线导致整个规划失败。
