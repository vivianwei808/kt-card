# G-06 四件套与「先合并再选边」

> 节点是工位，边是路牌，状态是工单，终态是结果章；选边必须在合并之后。

## 机制

- NodeSpec：一个节点只办一件事，读不可变 GraphState，只返回 StateDelta。
- EdgeSpec：自己不干活，只回答这一步做完该去哪一站。
- GraphState：公共工单，节点不直接改它，由执行器统一 apply。
- 终态：END、GUARDED、PREFLIGHT_FAILED，拿到明确结果才结束。
- 执行三步：执行当前节点、把 delta 合入状态、按新状态选下一条边。
- 先合并再选边：否则读到的还是上一轮结果，可能走错门。
- 两道护栏：业务轮次入口检查取消，maxSteps=25 防止图无限兜圈。

## 代码落点

- `NodeSpec / EdgeSpec / GraphDefinition / GraphState / GraphDelta`
- `LightGraph.run()`：apply 之后再 nextTargets
- `LightGraph 构造参数 nodeTimeoutMs=5000、groupTimeoutMs=10000`

## 复用清单

- 状态更新与路由选择拆成两步，顺序写进注释和测试。
- 给执行器设 maxSteps，任何图都需要一个兜底。

## 面试一句话

图执行永远是先合并状态再选边，否则路由读的是旧状态；这是最容易写反的一行。

## 常见坑

先选边再合并。单线程时偶尔能跑，一旦并行或返工就出现幽灵状态。
