# C-03 淘汰级联：丢了什么必须可观察

> 全放、去画像、压历史，三级依次降级，每一次取舍都记录原因。

## 机制

- 先按 (1 - safetyMargin) 计算可用预算，6000 的配置实际按 5100 装。
- 装不下时第一级丢画像，记录 droppedSections = profile: 剩余预算不足。
- 还装不下时第二级压历史，完整 JSON 换成最小摘要，记录 history-detail。
- 指令区、约束区、返工意见永不淘汰。
- 首轮没有历史区，第二级级联不应误报。
- 不可见的决策等于不存在的决策：裁剪结果必须进事件流，才能回答「这一轮为什么没带画像」。

## 代码落点

- `ContextAssembler.java L54-L66`：dropped 列表与两级级联
- `PlanChatService.java L191-L195`：CONTEXT_ASSEMBLED 事件四字段
- `PromptDumper.java`：每次调用前完整落盘，按 ### SECTION 切段计量

## 复用清单

- 给组装器加一个「决策日志」，记录 included、dropped 和原因。
- 测试里断言：紧预算时画像先丢、约束仍在。

## 面试一句话

裁剪过程可追踪，不代表 token 估算精确；我用 included/dropped 证明关键约束在裁剪后仍然保留。

## 常见坑

静默丢弃。线上出现「模型忘了预算」，排查时找不到任何证据。
