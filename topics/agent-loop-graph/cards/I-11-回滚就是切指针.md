# I-11 回滚就是切指针

> 每版追加一条记录，回滚把指针指回去，0 次模型调用。

## 机制

- 版本链记录：改了什么、终态、几轮、估算 token。
- 用户觉得 v3 不如 v2，把指针指回 v2 即可。
- 反面做法是用 v2 的参数重跑：模型非确定性，你会得到「差不多但不一样」的东西，那属于又赌一次。
- 回滚三步：非终态返回 409；版本不存在给出可选列表；都对则原样设回请求、响应、终态、版本号。
- 和预检、断线恢复同一条主线：最省钱的操作是不调用。
- 历史版本是确定的，这个确定性本身就是产品价值。

## 代码落点

- `PlanningVersion / PlanningSessionStore`：版本链
- `PlanningSessionStore.restore()`：切指针实现
- `PlanningRollbackTests`：断言 calls == 0

## 复用清单

- 任何生成类功能都保留版本链，回滚按指针切，不按参数重算。
- 给回滚写断言：模型调用次数必须为 0。

## 面试一句话

回滚不重跑，切指针；重跑得到的是另一个随机结果，不属于回滚。

## 常见坑

把回滚实现成「用旧参数再生成一次」。慢、贵、结果还不一样。
