# C-09 显式约束压过历史画像

> 用户这次说的精确数字，永远比历史推断优先；不需要额外的冲突仲裁器。

## 机制

- 场景：画像说「预算通常 2500-3000」，本次请求写「预算 2600」。两条信息重叠，听本次的。
- 实现上不写仲裁逻辑：四分区顺序本身就是冲突规则，约束区排在画像区之上。
- 召回偏好时跳过已被本次请求明确指定的字段，覆盖自动发生。
- 画像内部两条自相矛盾（「总选民宿」与「接受连锁酒店」）不该靠召回时仲裁，它在写入时就不该发生。
- 所以删除必须是一等公民：写入侧的严格，换来读取侧的简单。

## 代码落点

- `ContextAssembler`：约束区与画像区的顺序
- `PreferenceMemoryService`：召回过已指定字段
- `RevisionPolicy`：本次请求字段的校验与合并

## 复用清单

- 做个性化推荐时，把「本次显式输入」放在最高优先级，别写复杂的打分融合。
- 冲突规则尽量靠数据结构的顺序表达，少写 if-else。

## 面试一句话

显式优先于隐式，这条规则由分区顺序保证，不靠运行时仲裁器。

## 常见坑

遇到冲突就加一个融合算法。规则越复杂，越难解释为什么推荐了这个。
