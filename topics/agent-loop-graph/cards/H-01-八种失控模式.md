# H-01 八种失控模式

> 原地类四种：空转、震荡、发散、资源爆炸；进攻类四种：幻觉推进、补偿过度、卡死、权限逃逸。

## 机制

- 空转：每轮有输出但结果没有实质变化。单看每个组件都正常。
- 震荡：两个修复互相撤销，A 到 B 再到 A，在变但永远不收敛。
- 发散：从目标问题滑向相邻问题，模型的完成主义让它想把一切变好。
- 资源爆炸：每轮消耗递增，上下文线性或指数膨胀。
- 幻觉推进：模型报告已完成，实际什么都没做对。比空转更危险。
- 补偿过度：一个错触发连锁修补，每步局部合理，整体越来越偏。
- 卡死：等待永远不会来的响应，轮次计数器不递增，基于轮次的上限完全失效。
- 权限逃逸：为完成目标做超出授权的操作。

## 代码落点

- `LoopGuardrail 的四种 stop code 分别对应其中几类`
- `PlanningTerminalState.GUARDED`：受保护结束
- `第6章 6-1 的实测`：三轮一模一样的 C6 失败，12100 token 白花

## 复用清单

- 接手任何 Agent 系统，先对照这八种模式做一次风险画像。
- 给每种模式指定一道防线，写进设计文档。

## 面试一句话

Agent 的失控不是意外，是没有护栏时的默认行为；八种模式基本覆盖了常见故障。

## 常见坑

只防「跑太久」。空转、幻觉推进、权限逃逸都不靠时间兜底。
