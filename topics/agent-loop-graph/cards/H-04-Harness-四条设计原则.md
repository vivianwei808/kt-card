# H-04 Harness 四条设计原则

> 控制权分离、预算先行、可观测优先、优雅降级。

## 机制

- 控制权分离：执行者和终止者不能是同一实体，代码路径物理隔离。
- 预算先行：启动前确定边界，预算属于启动条件，不是跑起来再看。
- 可观测优先：不能终止看不见的东西，先确保数据可采集，再写终止逻辑。
- 优雅降级：终止不等于丢弃，交出最好的中间结果，说清停的原因。
- 权责分配：用户负责启动与取消，宿主负责每轮判断与终止，模型只决定单轮内的生成与工具使用。
- 被拦住的 Agent 像准时下班的员工，到点走，但交代得清清楚楚。

## 代码落点

- `LoopGuardProperties`：预算先行
- `PlanningLedger / PlanningLedgerSnapshot`：可观测
- `PlanningStopReport`：优雅降级的四要素

## 复用清单

- 新系统启动时强制要求填三个数：最大轮次、最大预算、最大时长。
- 终止路径必须返回结果对象，不能只抛异常。

## 面试一句话

护栏有四条设计原则，其中最容易忽略的是「可观测优先」：看不见的东西没法终止。

## 常见坑

终止时直接抛异常。用户拿不到任何中间结果，前面的钱全白花。
