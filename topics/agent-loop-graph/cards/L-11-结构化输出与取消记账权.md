# L-11 结构化输出与取消记账权

> 让模型按表格交付，同时删掉它的 total 字段：程序能算准的，不让模型算。

## 机制

- 自然语言给程序带来三个问题：无法确定性解析、无法精确寻址、每轮格式都在漂。
- 在 Loop 里问题被放大：第一轮输出要交给验证器，验证器结论要喂回下一轮。格式每轮变，Loop 就在跟格式搏斗。
- 一行 .entity(TripPlan.class) 把输出变成固定表格，框架负责告诉模型 Schema 并解析结果。
- 字段由验收标准反向推导：后面要检查什么，现在就保留什么。
- TripPlan 四层：TripPlan（根）、FlightLeg（C1）、DayPlan（住宿与星期）、Activity（C1-C7 全用）。
- 四个 record 里没有任何 total 字段，这是故意的。系统提示词明确禁止模型计算总金额。
- 解析失败走返工，不给任何失败开特殊通道：格式不合规和预算超支在 Loop 眼里是同一类事件。

## 代码落点

- `TripPlan / DayPlan / Activity / FlightLeg`
- `.entity(TripPlan.class)`
- `TripPlanConstraintReviewer`：消费结构化对象

## 复用清单

- 凡是程序要计算的数据，都定义 Schema，时间用 HH:mm，金额用整数加固定单位，类型用枚举。
- 把「模型不该算的东西」从 Schema 里删掉，并在提示词里明说。

## 面试一句话

我把总花费字段从 Schema 里删了，因为模型做加法是猜数；记账权收回到程序。

## 常见坑

保留 total 字段并用于校验。验证一个模型自报的数字，等于没验证。
