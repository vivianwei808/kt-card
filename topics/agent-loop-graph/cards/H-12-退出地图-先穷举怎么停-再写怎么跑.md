# H-12 退出地图：先穷举怎么停，再写怎么跑

> 六行表格先于代码存在，每行对应一种终态和一种用户动作。

## 机制

- 六种出口：参数错误（400）、预检拒绝（INFEASIBLE / UNSUPPORTED）、验收通过（SUCCESS）、护栏拦下（GUARDED）、模型失败（502）、用户取消（CANCELLED）。
- 每行写清：什么时候发生、终态是什么、模型调用几次。
- 预检和参数错误都是零次调用，最省钱。
- 退出地图先于代码：先画表，再实现，最后用测试逐行验收。
- 这个方法不限于 Agent，任何有多种结束方式的流程都适用：支付、审批、状态机。
- 表格同时是测试清单：每行至少一个场景。

## 代码落点

- `第6章 6-5 的退出地图`
- `Chapter6ExitMapReplayTest`：六类出口的固定回放
- `scripts/course/ch06-exit-map-replay.sh`

## 复用清单

- 新流程设计先交一张退出地图，评审通过后再写代码。
- 每个出口配一个测试，断言终态、轮次、调用次数。

## 面试一句话

我先画退出地图再写循环；每种「停」都有名字、有证据、有测试。

## 常见坑

先写主流程，出口靠 if 补。补到后面，没人说得清一共有几种结束方式。
