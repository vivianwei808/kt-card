# L-10 七条交付标准 C1-C7

> 五个 HARD 全过才算完成，两个 SOFT 进报告不阻塞。

## 机制

- C1 预算：机票 + 住宿 + 去重门票的真实总和不超过预算，同时检查酒店每晚限价。
- C2 时间冲突：同一天活动不重叠，结束必须晚于开始，首尾相接允许通过。
- C3 闭馆日：每天日期换算成星期，与景点闭馆日比对。
- C4 营业时间：活动时段完整落在开放时间内，餐饮与交通不检查。
- C5 路线衔接（SOFT）：跨区不超过 2 次，跨区间隔至少 40 分钟。
- C6 必去景点：用户点名的全部出现，支持「灵隐 / 灵隐寺 / 飞来峰」别名对齐。
- C7 每日节奏（SOFT）：每天 2-4 个景点、总时长不超过 540 分钟、11:00-14:00 有午餐；首末日不查下限。

## 代码落点

- `BudgetConstraintCheck / TimeConflictConstraintCheck / ClosedDayConstraintCheck / OpeningHoursConstraintCheck`
- `RouteContinuityConstraintCheck / MustVisitConstraintCheck / DailyPaceConstraintCheck`
- `looptrip.constraints.route.max-cross-area-per-day=2 / min-transfer-minutes=40`
- `looptrip.constraints.pace.max-activity-minutes-per-day=540`

## 复用清单

- 把这七条当成模板：钱、时间、空间、偏好四个维度各取一两条。
- 每条标准都配一个可配置阈值，调参不改代码。

## 面试一句话

七条标准分五硬两软，覆盖钱、时间、空间、偏好；每条都有证据和修复建议。

## 常见坑

只做预算和时间。闭馆日、营业时间这类硬事实反而最容易被用户投诉。
