# C-04 四种压缩手段，从轻到重

> 选择性注入、摘要替代原文、滑动窗口、结构化替代自然语言。

## 机制

- 选择性注入：本次已写死的字段不再被画像覆盖，条件不匹配的偏好不进来。
- 摘要替代原文：上一版完整 JSON 换成航班、酒店、景点摘要，续修轮从几百 token 降到可接受范围。
- 滑动窗口：只保留最近 N 轮，本项目天然只带上一版。
- 结构化替代自然语言：散文有歧义，键值对更精确、可寻址、长度通常减半。
- 压缩的终点是「更结构化的数据」，不是「更短的话」。
- 不要调模型做摘要：形成递归调用，复杂度和成本都不可控。

## 代码落点

- `ContextAssembler.minimalHistorySection()`：最小历史摘要
- `TripPlan 的 FlightLeg / DayPlan / Activity`：结构化摘要的字段来源
- `Prompt R 的约束`：不要调模型做摘要

## 复用清单

- 优先把「上一版全文」换成「上一版的关键选择 + 待修问题」。
- 任何摘要逻辑都用确定性代码实现，别引入第二次模型调用。

## 面试一句话

我的压缩终点是结构化，不是缩短；摘要是程序算的，不调模型。

## 常见坑

用 LLM 做摘要。多一次调用、多一份不确定，还可能把硬约束摘要掉。
