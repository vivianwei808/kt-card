# R-01 60 秒项目总览：四段结构

> 业务任务、控制闭环、架构演进、验证与边界；每段只埋一个追问入口。

## 机制

- 业务任务：多重约束下生成可被程序验收的旅行行程。
- 控制闭环：结构化契约、四个只读工具、两层验收、Loop 与 Harness。
- 架构演进：独立依赖与不同失败影响出现后，才从 Loop 迁到 Graph。
- 验证与边界：测试、断言、故障注入、事件日志、同条件计时；本地快照与非生产边界。
- 总览的任务是留下追问入口；一分钟讲不完整个项目，也不必讲完。
- 四个入口：只读工具、两层检查、四道护栏、为什么上任务图。

## 代码落点

- `项目定位`：LoopTrip 旅行规划 Agent
- `技术栈`：Java 21 / Spring Boot 3.5.8 / Spring AI 1.1.2 / Vite 7 + React 19
- `规模`：121 个主类、43 个含 @Test 的测试类、176 个用例、8 节点 16 边

## 复用清单

- 把四段写成四句话，背熟，每段留一个钩子。
- 开场从业务难点讲起，不要从技术栈背起。

## 面试一句话

它解决的是多重约束下的行程生成，我负责输出契约、执行控制与图迁移，证据是测试、回放与同条件计时。

## 常见坑

一分钟讲完技术栈。面试官听完不知道你解决了什么问题。
