# R-02 RAG 三段：索引、检索、生成

> 知识切块转向量入库，查询时召回相关块并重排，最后拼进上下文交给模型生成。

## 机制

- Indexing 解决怎么存：收集多源数据、文档分块、用 BGE 或 M3E 等模型向量化入库。
- Retrieval 把问题转向量，在向量库做相似度检索，再对结果重排序。
- Generation 把检索片段和用户问题组装成上下文，交给 LLM 生成答案。
- 分块策略要在语义完整性与检索效率之间取得平衡。
- 检索走偏，后面生成质量必然下降。

## 代码落点

- `BGE / M3E`：embedding 模型
- `FAISS / Chroma`：向量库
- `Rerank`：召回后重排
- `context`：拼进 prompt 的片段

## 复用清单

- 画架构图按三段分开，每段单独定指标。
- 排障时先确认召回块对不对，再看生成。

## 面试一句话

RAG 就三段：索引、检索、生成，绝大多数问题出在前两段。

## 常见坑

只调生成模型和提示词，不检查召回是否找对了块。
