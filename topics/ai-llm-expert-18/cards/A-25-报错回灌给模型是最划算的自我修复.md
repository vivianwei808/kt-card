# A-25 报错回灌给模型是最划算的自我修复

> 执行报错时把错误信息和原代码一起喂回 LLM，max_retries=3 能修掉八成 Pandas 类型错误。

## 机制

- 直接在宿主机跑 LLM 生成的代码有风险，可能含 rm -rf 或死循环。
- 沙箱方案用 Daytona、E2B 或自建 Docker，每次执行起隔离容器，只取回 stdout 和 stderr。
- 执行超过 30 秒或内存溢出直接销毁容器，主进程不受影响。
- 自我修复是 while 循环：拿到 Error 后不抛给用户，把错误信息和原代码回灌让模型重写。
- max_retries=3 时约 80% 的 Pandas 数据类型错误能被自动修好。

## 代码落点

- `Daytona / E2B`：代码沙箱
- `Code Interpreter`：执行环境
- `max_retries=3`：重试上限
- `stdout / stderr`：回灌内容

## 复用清单

- 生成的代码一律进沙箱执行，不在宿主机跑。
- 报错先回灌一次，再决定是否抛给用户。

## 面试一句话

代码 Agent 的可靠性来自沙箱隔离和错误回灌，重试三次能修掉多数类型错误。

## 常见坑

把报错直接抛给用户，白白浪费一次可自愈的机会。
